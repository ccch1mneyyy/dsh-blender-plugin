## 0. 设计决策（不可动摇）

| 决策 | 理由 |
|---|---|
| **宿主集成能力走独立 HTTP 路由 `/host/*`，不进 `/plan` 的 op 目录、不加模型工具** | 这是**用户侧**能力（人点视口 → 进自己的消息），不是模型工具。不进 op 目录 ⇒ `tests/capability.lock.json` 不变、`runtime/catalog.mjs`/`engine.mjs` 目录面不变 ⇒ **15 个模型工具与 186 个 op 零回归风险** |
| **不新增任何 npm 依赖、不引入打包器** | 客户端半边**手写** `src/client/index.js`（`window.__ModuleLoader__.load` 格式，纯 JS，零 `require` 依赖或只 `require('react')` 等 baseline）。本机到 `github.com` 不通，装新依赖不可靠 |
| **不改 Blender addon** | addon 是共享底座、由用户自备。pick 的反投影用插件已有的 `runtime/view.py`（`make_view_matrix`/`make_proj_matrix`/`matrices_json` 已存在）在 Blender 侧算，**不需要 addon 新命令** |
| **CORS 只对 loopback 放行** | 面板从 DSH GUI 源（`http://127.0.0.1:3080`）跨源调 `127.0.0.1:9877`，必须带 CORS 头；但只回显 loopback Origin，不放行任意站点 |
| **pick 必须拒绝错配** | 截图所属的 `.blend` / 场景与 Blender 当前不符时**拒绝**并回 `*_mismatch`，绝不把点击投到当前场景（对齐上游 `addon.py:2188` 的纪律） |

## 1. 后端 HTTP 契约（`runtime/server.mjs` 新增）

**前缀**：`/host`。**所有** `/host/*` 响应（含错误）都必须带 CORS 头。

### 1.1 CORS（所有 `/host/*`，含 `OPTIONS`）

请求头 `Origin` 为 loopback 时回显：
- `Access-Control-Allow-Origin: <请求的 Origin>`（仅当 Origin 匹配 `^http://(127\.0\.0\.1|localhost)(:\d+)?$`；否则**不加该头**）
- `Access-Control-Allow-Methods: GET, POST, OPTIONS`
- `Access-Control-Allow-Headers: content-type`
- `Access-Control-Max-Age: 600`
- `Vary: Origin`

`OPTIONS /host/*` → **204**，空体。

### 1.2 `GET /host/view/latest?since=<int>`

返回最近一次视口捕获的**状态**（不含图像字节）。`since` 可省（默认 0）。

```json
{ "ok": true,
  "seq": 3, "captured_at": 1750000000.125, "source": "user",
  "file": "/home/x/proj.blend", "scene": "Scene", "scene_count": 1,
  "stale": false, "scene_revision": 12, "revision_stale": false,
  "pickable": true, "blender_quiet": true,
  "width": 800, "height": 450 }
```

| 字段 | 类型 | 语义（**必须**） |
|---|---|---|
| `seq` | int | 单调递增；**没捕获过任何一帧时为 `0`** |
| `source` | `"user"｜"auto"｜"model"｜"none"` | 谁触发的这次捕获；`seq===0` 时 `"none"` |
| `captured_at` | float\|null | Unix 秒；`seq===0` 时 `null` |
| `file` | string\|null | 该帧所属 `.blend` 的**绝对路径**（未保存为 `null`） |
| `scene` | string\|null | 该帧所属场景名 |
| `scene_count` | int\|null | 捕获时 `len(bpy.data.scenes)` |
| `stale` | bool | 该帧之后场景被改过（用"变更命令计数"判定，见 §3） |
| `scene_revision` | int\|null | v2.3：GUI 编辑 revision（Blender 侧 depsgraph handler 写的计数）；探针未注入/读不到时为 `null` |
| `revision_stale` | bool | v2.3：`scene_revision` 与该帧捕获时的 revision 不同（鼠标改场景也算）；没有 revision 时恒 `false` |
| `pickable` | bool | **该帧是否可点击反投影**（没有矩阵就必须 `false`，不许撒谎） |
| `blender_quiet` | bool | 当前无在飞命令且距上次命令 ≥ `AUTO_CAPTURE_QUIET_S`(0.8s) |
| `width`/`height` | int | 图像像素尺寸 |

### 1.3 `GET /host/view.png?seq=<int>`

- `seq` 等于当前 `seq`（或省略 `seq`）→ **200** `image/png`（`cache-control: no-store`）
- `seq` 落后或未知 → **409** JSON `{ "ok": false, "error": "stale_seq", "seq": <当前> }`
- 还没有任何帧（`seq===0`）→ **404** JSON `{ "ok": false, "error": "no_frame" }`

### 1.4 `POST /host/view/capture`

请求体（可省字段）：`{ "max_size": 1000, "auto": false }`
- `max_size`：最长边像素，夹到 `[200, 2000]`，默认 `1000`
- `auto`：`true` ⇒ `source="auto"`（面板自动重拍），`false` ⇒ `source="user"`

响应：**200**，体与 §1.2 同形（即最新状态）。捕获失败 → **502** `{ "ok": false, "error": "<原因>" }`。

### 1.5 `POST /host/view/pick`

请求体：`{ "seq": 3, "x": 0.5, "y": 0.25 }`
- `x`,`y`：**0..1 归一化**，**图像左上角为原点**，`y` 向下。超出范围夹到 `[0,1]`

响应：

| 情形 | HTTP | 体 |
|---|---|---|
| 命中物体 | 200 | `{ "ok": true, "object": { "name": "Cube", "type": "MESH", "detail": "MESH 8v/6f", "location": [0,0,0] } }` |
| 点在空处 | 200 | `{ "ok": true, "object": null }` |
| `seq` 未知/无矩阵 | 200 | `{ "ok": false, "error": "unknown_seq" }` |
| `.blend` 错配 | 200 | `{ "ok": false, "error": "file_mismatch", "expected": "<截图所属>", "current": "<Blender 当前>" }` |
| 场景错配 | 200 | `{ "ok": false, "error": "scene_mismatch", "expected": "Scene", "current": "Scene.001" }` |
| Blender 不可达 | 502 | `{ "ok": false, "error": "<原因>" }` |

> **纪律**：错配**必须**返回 `*_mismatch`，**不得**降级为"投到当前场景"。

### 1.6 `GET /host/scene-items?q=<str>&limit=<int>`

供 `@` 提及用。`q` 大小写不敏感子串过滤（空=全部）；`limit` 默认 200、夹到 `[1, 1000]`。

```json
{ "ok": true,
  "objects":     [ { "name": "Cube", "type": "MESH" } ],
  "materials":   [ { "name": "Mat" } ],
  "collections": [ { "name": "Collection" } ] }
```
排序：按 `name` 升序（稳定）。Blender 不可达 → 502 `{ "ok": false, "error": "<原因>" }`。

### 1.7 `GET /host/scene-revision`（v2.3）

GUI 编辑 revision 探针。面板用它识别"鼠标在 Blender 里改了场景"（这种改动没有后端命令，
`stale` 不会变）。

```json
{ "ok": true, "revision": 12, "last_edit_at": 1792397256.38,
  "idle_ms": 812, "heartbeat_at": 1792397270.14, "pid": 133585,
  "version": 1, "fresh": true, "revision_stale": true }
```

| 字段 | 类型 | 语义 |
|---|---|---|
| `revision` | int | 从 0 开始单调递增；Blender 重启后归零 |
| `last_edit_at` | float\|null | 最近一次 depsgraph 更新的 Unix 秒；从没改过为 `null` |
| `idle_ms` | int\|null | 距最近一次编辑的毫秒数（面板用它做 0.8 s 停稳判定） |
| `heartbeat_at` | float\|null | 探针心跳（2 s 一次）；过期说明 Blender 重启/探针丢失 |
| `pid` | int\|null | Blender 进程号 |
| `version` | int\|null | 探针版本 |
| `fresh` | bool | 心跳是否仍新鲜 |
| `revision_stale` | bool | `revision` 与当前帧捕获时的 revision 不同（§1.2） |

实现：后端首次访问时把 `runtime/scene_revision.py` 注入 Blender（`execute_code`，只注入一次）；
模块在 `depsgraph_update_post` 里累加 revision，并写共享 workDir 的 `scene_revision.json`（2 s 心跳）。
**常态零 addon 往返**；心跳过期（Blender 重启）时后端会重新注入。读不到文件/注入失败 → `{ "ok": false, "error": "..." }`，
面板回退到只有 `stale` 的自动重拍。

## 2. 客户端半边契约（`src/client/index.js` → `lib/client.js`）

### 2.1 包声明（Lead 负责改 `package.json`）

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "inject": [], "platform": "web" }
},
"exports": {
  ".": { "types": "./lib/types/index.d.ts", "default": "./lib/index.js" },
  "./client": { "default": "./lib/client.js" },
  "./package.json": "./package.json"
}
```

> **与初稿的两处差异（Lead 于实现期按实况校准，2026-10-16）**：
> 1. `client.inject` 为 `[]` —— bundle 运行时**只 `require("react")`**（react 是 shell seed，不是包行），
>    服务依赖走 cordis 的 `inject: ["slots"]`（**服务名**，与 coc-dice 同款）。本机 `dsh-divination-108`
>    用的也是 `inject: []`，属已验证形态。**不列**未 `require` 的包行。
> 2. `"./client"` **不写 `types`** —— `lib/**` 是构建产物，客户端半边是手写 JS、tsc 不为其产出声明；
>    指向一个不存在的 `.d.ts` 只会留下悬空路径。DSH 加载器只需要运行时 bundle。

### 2.2 bundle 格式（**必须逐字**，照本机 coc-dice 的活样板）

```js
window.__ModuleLoader__.load({
  id: "@dsh-external/dsh-blender-plugin",
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    // …实现…
    exports.apply = apply;    // cordis 插件：apply(ctx)
    exports.inject = inject;  // 字符串数组
    return module.exports;
  }
});
```

- `id` **必须**等于包名
- 工厂内可 `require("react")`（本机 core client-ui 包即如此，baseline 提供）
- **不得** `import`/`export` 语法、不得顶层 await、不得引用 Node 内置模块

### 2.3 面板（视口）

- 座位：**`conversation.view`**（list/session 槽位，常开）。注册方式（**双参数正规写法**）：
  ```js
  ctx.slots.inject('conversation.view', () =>
    ctx.slots.register({ name: 'conversation.view', id: '<包名>-viewport', label: () => 'Blender 视口' },
                       ViewportPanel));
  ```
  ⚠️ 不要学 coc-dice 把 `component` 塞进 options（那是 `component===undefined` 的绕法）
- 轮询 `GET /host/view/latest`：常规 **1500 ms**；`stale===true` 时 **600 ms**；v2.3 起同一拍先取 `/host/scene-revision`，`revision_stale && idle_ms>=800` 也算 stale
- `seq` 变大 → `<img src="http://127.0.0.1:9877/host/view.png?seq=<seq>">`
- `pickable===false` 时：图像可点但只"附整图"，并显示"刷新后可按物体点选"
- 点击图像：归一化坐标 → `POST /host/view/pick` → 命中则加标记；**已选中的对象再点一次取消**
- 点空处 → 清空已选（只附整图）

### 2.4 点击 → 进下一条消息（**DSH 没有 Codex 的 modelContext，按此实现**）

点击**不自动发送**；面板底部一个「加入消息」按钮，按下后：
1. 取当前帧：`fetch(BACKEND + '/host/view.png?seq=' + seq)` → `blob` → `new File([blob], 'blender-viewport.png', {type:'image/png'})`
2. `const drafts = ctx.conversation.createDrafts(sessionId, [file])`
3. `inputActions.addAttachments(drafts.map(d => d.id))`
4. `inputActions.insertText(text, inputActions.captureInsertion())`，`text` 规则：
   - 有选中对象：`Blender 视口点击：<name>（<detail>）。用户说"这个/这些"时指它们；对象名在 bpy.data.objects 里可直接用。`
   - 无选中：`附上当前 Blender 视口截图。`
5. `ctx.conversation.input.for(actx).notify('info', '已加入消息')`（可用则用，不可用静默）

> `inputActions` 来自 session 作用域槽位组件 props（`SessionStandardProps`）。若该座位拿不到，则用 `ctx.conversation.input.for(actx)` 的 `SessionInput`（有 `setDraft`/`addAttachments`/`notify`）。

### 2.5 `@` 提及源

> **ref 形态（2026-10-16 Lead 裁决，消除歧义，字段名未改）**：`ref` **带前缀** ——
> 对象 `object:<name>` · 材质 `material:<name>` · 集合 `collection:<name>`；
> **`codec` 负责拆前缀**取裸名（`splitRef`：前缀不是这三个之一、或没有前缀时按 `object` 兜底）。

```js
ctx.effect(() => ctx.inputTriggers.registerSource({
  trigger: '@', name: 'blender',
  candidates: async (session, req) => (await fetchItems(req.query)).map(...),   // → InputTriggerCandidate[]
  onPick: (pick) => ({ insert: { source: 'blender', ref: '<kind>:<name>', label: '<name>',
                                 appearance: 'file', clipboardText: '@<name>' } }),
  codec: {
    clipboardText: (ref) => '@' + splitRef(ref).name,                    // 先拆前缀，再取裸名
    serialize: async (ref) => { const p = splitRef(ref);                 // '<blender-object>Cube</blender-object>'
      return '<blender-' + p.kind + '>' + p.name + '</blender-' + p.kind + '>'; }
  }
}));
```
- 候选数据源：`GET /host/scene-items?q=<query>`
- `candidates` 返回 `InputTriggerCandidate{name, label?, description?, icon?, section?}`；**没有缩略图字段**，用 `section` 分组（`对象`/`材质`/`集合`）
- 失败必须**不抛**（返回 `[]`），否则会污染输入框
- 投影对照（`splitRef` 口径）：
  | ref | `clipboardText(ref)` | `serialize(ref)` |
  |---|---|---|
  | `object:Cube` | `@Cube` | `<blender-object>Cube</blender-object>` |
  | `material:Mat` | `@Mat` | `<blender-material>Mat</blender-material>` |
  | `collection:Col` | `@Col` | `<blender-collection>Col</blender-collection>` |
  | `Cube`（裸 ref，无前缀） | `@Cube` | `<blender-object>Cube</blender-object>` |
  > 裸 ref 一行是"与旧示例 `'@' + ref` 逐字一致"的兼容点：`clipboardText('Cube') === '@Cube'`。

## 3. 后端内部语义（`runtime/viewstore.mjs` 新增）

- `seq` 从 1 起单调递增；`put(png, source, view, meta)` 时 `seq += 1`
- **场景变更计数**：捕获**开始前**读一次 `scene_version` 存为该帧的 `captured_scene_version`；任何"会改场景"的命令完成后 `scene_version += 1`；`stale = scene_version > captured_scene_version`
  - "会改场景"的命令集合（对齐上游 `SCENE_CHANGING_COMMANDS`）：`execute_code`、`/do`、`/act`、`/headless`、`/plan` 的写 op、`/txn` 的 restore、`/preset` 的 apply、资产导入类
- **在飞计数**：命令开始 `+1`、结束 `-1`；`blender_quiet = (在飞===0) && (now - last_command_at >= 0.8)`
- `_views`：`seq → {view_matrix, window_matrix, width, height, file, scene}`，**只保留最近 50 帧**
- 面板轮询只读 store，**绝不**因为轮询去碰 Blender（面板开着不能占 Blender 主线程）

## 6. 实现注记（Implementation notes）

> **本节是追加的注记，不改上面任何已冻结字段。** 记录"测试怎么打这些判据"与"发现的口径歧义"。
> 追加时间：**2026-10-16**（tests-docs）。

### 6.1 两条自检入口（都不进 `npm test`）

| 命令 | 覆盖 | 不可用时 |
|---|---|---|
| `node tests/client_bundle_selftest.mjs` | §4 判据 9（bundle 可装载）+ §2.2 的格式约束 | `lib/client.js` 不存在 → 打印 `SKIP: lib/client.js 尚未生成`，**exit 0** |
| `node tests/host_routes_selftest.mjs` | §4 判据 1–8 + §1 若干显式字段 | 后端不可达 → SKIP exit 0；后端在但 `/host` 未装载 → SKIP exit 0；Blender 不在 → 判据 1/2 照跑，3–8 SKIP exit 0 |

**测试口径（不是放宽断言，是环境不确定时的诚实三态）**：

1. **判据 5「点画面中心命中」**：自动测试无法保证"用户的视口中心一定有物体"。
   中心命中 → 断言 `name` 非空、且该名字**确实在 `/host/scene-items` 里**（=契约里的"预期对象"）。
   中心为空 → 退化为 5×5 网格采样，任一点命中即通过并打印命中点；**全空则 SKIP**（不是失败）。
2. **判据 6「点 (0.01,0.01) 为 null」**：若该角落**恰好**有物体，服务端返回该物体是**正确行为** → SKIP 并打印回执，不判失败。
3. **判据 7「错配拒绝」**：需要让"当前场景"与"截图所属场景"不同。测试用 `POST /act` **临时把场景名改成 `<原名>.dshselftest`**，pick 后**在 `finally` 里改回并核验 `stdout`**；
   `DSH_HOST_TEST_NO_MUTATE=1` 可完全关闭这次改动（判据 7 转 SKIP）；`/act` 回 `409 leased` 时**不夺租约**，同样转 SKIP。
   **未在测试里覆盖**：`file_mismatch`（构造它需要动 `.blend` 文件路径，风险高于收益）—— 手测：切到另一个 `.blend` 后用旧 `seq` 点。
4. **§1.4 `max_size` 上界**：下界（100 → 200）断言**相等**；上界只断言 **≤ 2000**，因为"不放大超过原生视口"也符合"夹到 [200,2000]"。
5. **§1.3 `seq=0` 而 store 已有帧**：契约只写了"还没有任何帧时 `seq===0` → 404"，未定义"已有帧却传 `seq=0`"。测试**只打印回执、不判定**。
6. **§1.1「所有 `/host/*` 响应（含错误）带 CORS」**：已知路由（含 `png` 的 404 `no_frame`、409 `stale_seq`）**断言**带 ACAO；
   **未知 `/host/*` 路径**（面板永不触达）若未带 ACAO，只打 `WARN`，不计失败。

### 6.3 `ref` 口径（Lead 2026-10-16 裁决）

# 7. v1.2 增补（右侧栏面板 + 模型请求点选）

> 冻结时间：**2026-10-16** ｜ 用户裁决：① 面板**只在 Blender 通道可用时出现**（右侧栏座位）；② 模型请求点选走**阻塞式**（点完直接返回对象名）。
> **§1–§6 一字不动**；本节是**增量**。字段名/状态码同样冻结。

## 7.1 就绪端点（门控的唯一依据）

### `GET /host/ready`

**必须便宜**：只读后端**已缓存**的通道状态，**不得**触发 bpy 往返（实测 `/health` 2.6 ms vs `/doctor` 205 ms）。

```json
{ "ok": true, "ready": true, "addon": true, "protocol": 11,
  "backend": "1.2.0", "reason": null }
```

| 字段 | 语义 |
|---|---|
| `ready` | 后端存活 **且** addon 握手健康 ⇒ `true`；否则 `false` |
| `addon` | addon 是否已 Connect（同上，独立字段便于诊断） |
| `protocol` | 最近一次握手的协议号；未知为 `null` |
| `reason` | `ready=false` 时给 `"addon-unreachable"` / `"handshake-stale"` / `null` |

**CORS 同 §1.1**（loopback 才回显 ACAO）。

## 7.2 点选请求（阻塞式交互）

全局**至多一个** pending 请求；新请求把旧的置为 `cancelled`（`reason:"superseded"`）。

### `POST /host/pick/request`

体：`{ "prompt": "请点一下你要改的物体", "timeout_s": 120 }`（都可省）
- `prompt` 缺省 `"请点一下你要改的物体"`；**最长 200 字符**，超出截断
- `timeout_s` 缺省 `120`，**夹到 `[5, 600]`**

响应 **200**：
```json
{ "ok": true, "request": { "requestId": "pk-3-1792100000", "prompt": "…",
  "created_at": 1792100000.1, "expires_at": 1792100120.1 } }
```

### `GET /host/pick/request`

面板用。响应 **200**：`{ "ok": true, "request": {…} | null }`（只回 pending 的那个；过期则先判过期再回 `null`）。

### `POST /host/pick/answer`

体：`{ "requestId": "…", "seq": 3, "x": 0.5, "y": 0.5 }`
- 用与 §1.5 **完全相同**的 pick 逻辑（含 file/scene 错配拒绝）

| 情形 | HTTP | 体 | 请求状态 |
|---|---|---|---|
| 命中物体 | 200 | `{ "ok": true, "state": "answered", "object": {…} }` | → `answered` |
| 点在空处 | 200 | `{ "ok": true, "state": "answered", "object": null }` | → `answered`（空处=用户明确表示"没有"） |
| `.blend`/场景错配 | 200 | `{ "ok": false, "state": "pending", "error": "scene_mismatch", "expected": …, "current": … }` | **仍 pending**（让用户刷新后重试） |
| `seq` 未知 | 200 | `{ "ok": false, "state": "pending", "error": "unknown_seq" }` | **仍 pending** |
| `requestId` 不存在/已结束 | 200 | `{ "ok": false, "state": "<当前态或 unknown>", "error": "no_such_request" }` | 不变 |

### `POST /host/pick/cancel`

体：`{ "requestId": "…", "reason": "user" }` → **200** `{ "ok": true, "state": "cancelled" }`（幂等：已结束也回 200，`state` 给实际态）。

### `GET /host/pick/result?requestId=…`

模型工具轮询用。**200**：
```json
{ "ok": true, "state": "pending|answered|cancelled|expired|unknown",
  "object": { "name": "Cube", "type": "MESH", "detail": "…", "location": [0,0,0] } | null,
  "error": null }
```
- `expired` 在**读取时惰性判定**（`now > expires_at` 且仍 pending）
- 结束态（answered/cancelled/expired）**保留最近 8 条**供查询，其余淘汰为 `unknown`

## 7.3 客户端：右侧栏座位 + "启用才出现"门控

1. **轮询 `GET /host/ready`，间隔 2000 ms**（便宜，可常开）。
2. **`ready===true` 才注册**（两阶段都包在 `ctx.effect` 里，注册寿命 = effect 寿命）：
   ```js
   const disposeType = ctx.sidebarRightTabs.register({
     id: '@dsh-external/dsh-blender-plugin',
     kind: 'blender-viewport',
     title: () => 'Blender 视口',
     guide: [{ id: 'viewport', title: 'Blender 视口', description: '看 Blender 当前画面，点物体写进消息' }],
   });
   const disposeBody = ctx.slots.register(
     { name: 'sidebar.right.pane.tab', key: '@dsh-external/dsh-blender-plugin' }, ViewportPane);
   ```
3. `false → true`：注册 + **自动开一次** `ctx.sidebarRight.openTab('blender-viewport')`（**每个会话只自动开一次**，用户手动关掉后不反复弹）。
4. `true → false`：`dispose()` 注销（窗口随之消失）；若标签页开着则关闭。
5. **降级**：若 `ctx.sidebarRightTabs` / `ctx.sidebarRight` 不存在（旧宿主），退回 §2.3 的 `conversation.view` 座位，并在面板里说明"右侧栏不可用，已退回对话页签"。
6. 面板 body 用 `useTabInfo()` 读 `{sidebar, panel, tab}`；`tab.navigation.params` 可省。

## 7.4 客户端：点选请求的 UI 与应答

- 轮询（同 §7.3 的 2000 ms tick，或面板自身 tick）`GET /host/pick/request`。
- **有 pending 请求**：面板顶部显著横幅「**模型请求你点选**：<prompt>」+「取消」按钮；此时**下一次点击走 `POST /host/pick/answer`**（不再走"加入消息"路径），并按回执处理：
  - `answered` → 横幅变「已应答：<name>（已返回给模型）」，2 s 后消失
  - `pending` + `scene_mismatch`/`unknown_seq` → 横幅显示「刷新后再点（<error>）」，保持等待
- **无 pending 请求**：维持 §2.4 的"点击 → 加入消息"路径。
- 取消按钮 → `POST /host/pick/cancel`。
- 面板不可见时不轮询（省资源）；但**模型请求期间若面板未打开**，`@`/草稿路径不受影响 —— 模型侧会自行超时。

## 7.5 模型工具（Lead 实现）

**新增第 16 个工具 `blender_rt_pick`**：
- 参数：`prompt`（string，可省）、`timeout_s`（integer，默认 120，夹 `[5,600]`）
- 行为：`POST /host/pick/request` → 每 **400 ms** 轮询 `/host/pick/result` → 直到 `answered`/`cancelled`/`expired`/`unknown`
- 返回：命中给 `name/type/detail/location`；空处给"用户点了空处（表示没有选中任何物体）"；超时/取消给可读原因
- **必须响应宿主取消**：用插件既有的 `execSignal()`；abort 时 `POST /host/pick/cancel`（`reason:"aborted"`）后退出
- `isConcurrencySafe: () => false`（全局单请求）；静态 `timeoutMs` 取 **180000**（> 默认 120 s）
- **能力面变化是刻意的**：`tests/capability.lock.json` 工具数 15 → **16**（用 `--update` 并写明理由）

6. **测试不抢占真人的 pending 请求**：跑 12–15 之前先 `GET /host/pick/request`，若已有 pending ⇒ **整组 SKIP**（§7.2 全局至多一个）；收尾把自建请求 `cancel` 掉，并断言"测试结束后不留 pending"。
7. **客户端静态断言**：契约没有冻结常量**名字** ⇒ "轮询 2000 ms"优先读 `__selftest` 暴露的常量，退回"源码里 `*ready*POLL* = 2000`"或"`/host/ready` 附近 400 字符内有 2000"两种等价证据；`guide` 只断言存在 `id:'viewport'` 与「Blender 视口」，**不钉** description 文案。
8. **客户端值断言接受"命名常量"**（`literalOrConst`）：契约冻结的是**值**，不是"必须内联"。实测 client-ui 写的是 `var TAB_KIND = "blender-viewport"; … kind: TAB_KIND` 与 `key: TAB_ID` —— 按内联字面量断言会**误判成缺失**（首次回归就红了 3 条，全是假红）。现已同时接受"内联字面量"与"指向该值的命名常量"。
9. **判据 12/13 不因"视口里没有物体"整条 SKIP**：视口对着空处是用户的正常状态，而 §7.2 的 `pending → answered` 状态机在"点空处"时同样成立（`answered` + `object:null` = 用户明确表示"没有"）。测试先探命中点，探不到就**退化为空处应答**照跑状态机，只有"`object.name` 是预期对象"这一条 SKIP。判据 13 的错配判定发生在射线投射**之前**，所以本来就不需要命中点。
10. **并发护栏（`currentSceneName()`）**：判据 7/13 靠"临时改场景名"构造错配，而**共享同一个 Blender 时别的会话可能也在改名** —— 实测两个 run 并发时，A 改完名、B 又改回去 ⇒ A 的 pick 拿到"命中"而不是 `scene_mismatch`，变成**假红**（本仓实测到过 2 条）。现在改名前/应答前会先核一次"当前场景名还是不是我设的那个"，不一致就**如实 SKIP**，不冤枉服务端。
11. **写租约默认绝不抢**；`DSH_HOST_TEST_FORCE_LEASE=1` 才带 `force:true`（用于"确认没有别人在驱动这个 Blender"时把最关键的判据 13 跑起来）。默认行为不变。

### 7.8.3 测试期发现的实现风险（**报 Lead / runtime-host**）

| # | 风险 | 证据 | 建议 |
|---|---|---|---|
| 1 | **`requestId` 的唯一性 —— 已核实：实现是对的 ✅**（原担心的误读路径仍值得记一笔） | 契约 §7.2 的**示例**格式 `"pk-3-1792100000"` 若把中间的 `<seq>` 理解成"**捕获 seq**"，则在同一秒内背靠背建两个请求（期间无新捕获 ⇒ seq 不变）会**撞 id** ⇒ `result?requestId=…` 无法区分两者、判据 15 会红（**我的 mock 按这种误读实现，确实复现了撞号**）。**但真机实测：实现用的是 `pk-<单调请求计数器>-<epoch秒>`** —— 背靠背两请求得到 `pk-6-1792100610` / `pk-7-1792100610`，**不撞号** ✅ | 实现无需改。建议把 §7.2 示例里的 `<seq>` 注明为"**请求计数器**"而非"捕获 seq"，避免后续实现者照字面误读 |
| 2 | `/host/ready` 不得在实现里"顺手做握手/探活" | 那会抬高 `metrics.calls`，判据 11 会红（实测真机：`ready` ×5 期间增量 **0**，中位数 **1 ms**，对照 `/doctor` **236 ms**） | 保持"读后端已缓存的通道状态"（§7.1 已写明） |

### 7.8.5 回归时的一个真实陷阱：**产物可能比源码旧**（本仓 2026-10-16 实测到）

| | |
|---|---|
| **现象** | `src/client/index.js` 已含 v1.2（`/host/ready` 命中 5 处），但 `lib/client.js` 还是旧构建（命中 **0** 处，mtime 比 src 早 ~38 分钟）⇒ 用户重启 DSH 拿到的是**旧客户端半边**：没有右侧栏门控、没有点选横幅；而模型侧工具已经在调 `/host/pick/request` |
| **怎么发现** | `node scripts/build-client.mjs --check` → **exit 1**，打印 `产物已过期 → lib/client.js` 与期望/实际 sha256 与字节数；`node tests/client_bundle_selftest.mjs` 会打印 `SKIP … bundle 里没有 /host/ready`（这正是它的价值：**产物没跟上源码时它不会假装绿**） |
| **修法** | `node scripts/build-client.mjs`（客户端半边改动后必须重建）→ 刷新页面 / 重启 DSH |

> 教训：`lib/**` 是**构建产物**，`src/**` 改了不等于线上改了。发版前跑一次 `--check` 是最便宜的保险。
